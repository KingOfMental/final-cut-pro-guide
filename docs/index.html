Library·Event·Project를 구분하기

Library는 편집 데이터와 미디어의 관리 단위, Event는 소재·프로젝트를 묶는 단위, Project는 실제 편집 타임라인이다. 파일이 들어 있는 폴더와 화면에서 분류한 Event는 같은 개념이 아니다.

왜 이 방법을 쓰는가

찾기 편한 구조와 저장 위치를 따로 설계하면 영상이 늘어도 혼란이 적다. 한 여행을 한 Library로 시작하고 날짜나 장면별 Event를 쓰는 것은 관리하기 쉬운 출발점이다.

실제 작업 순서

  1. Library를 만들고 이름에 프로젝트·연도를 넣는다.
  2. Event를 촬영일·소재·편집안 등 필요한 기준으로 나눈다.
  3. Project를 만들고 해상도·프레임률·색공간을 지정한다.
  4. 라이브러리 속성에서 미디어·캐시·백업 위치를 확인한다.

두 앱이 같은 원본을 찾게 하는 가져오기

FCP와 Resolve의 병행 작업은 같은 원본을 확실하게 참조하는 데서 시작한다. Event 분류는 FCP 편집 데이터이고, Resolve가 읽을 공통 폴더 구조와는 별개다.

왜 이 방법을 쓰는가

XML에는 편집 정보와 미디어 참조가 들어간다. 한 앱만 아는 원본 위치, 카드마다 반복되는 파일명, 서로 다른 프록시를 기준으로 삼으면 보정 이전에 재연결부터 틀어진다.

실제 Final Cut Pro 화면으로 확인

Apple 공식 가이드에서 가져온 실제 화면입니다. 이미지를 누르면 크게 볼 수 있습니다. 앱 버전·언어에 따라 표시가 다를 수 있습니다.

실제 작업 순서

  1. 프로젝트 루트 아래 01_ORIGINALS / 카메라 / 촬영일 / 카드 폴더를 만들고 원래 카드 구조를 보존한다. 작업용 원본과 별도 백업을 검증한다.
  2. FCP는 가능한 파일에서 Leave files in place로 공통 원본을 참조한다. 카드 포맷에 따라 이 옵션이 없으면 먼저 안전하게 가져오기·복사한 실제 미디어 위치를 기록한다.

타임라인 프레임률은 컷과 소리의 시간 기준이다. 24와 23.976, 30과 29.97은 비슷해 보여도 정확히 같지 않다. 4K라는 이름만으로 가로·세로 픽셀과 FPS가 정해지지 않는다.

왜 이 방법을 쓰는가

프로젝트를 만든 뒤 첫 클립의 설정에 무심코 맡기면 고속 촬영 FPS로 전체 편집이 시작될 수 있다. 왕복 작업은 양쪽 앱이 같은 시간 기준을 써야 한다.

실제 작업 순서

  1. 납품의 비율·해상도·FPS를 먼저 정한다.

마스크로 장소를 자연스럽게 바꾸고 싶다전경 이동과 A/B 겹침을 설계하고 마스크 경계를 맞춘다.인트로와 엔딩 구성이 고민이다같은 본편에 세 시작과 두 끝을 비교한다.전환 후 Resolve에서 화면이 달라졌다효과 담당과 원본 보정·구운 합성 전략을 확인한다.음악은 그대로 두고 파도 정점만 바꾸고 싶다Slip으로 컷 경계를 유지하고 원본 구간을 옮긴다.클립을 옮기니 음악과 타이틀이 따라온다연결점과 Primary Storyline을 먼저 확인한다.전체 길이는 유지하고 두 컷 배분을 바꾸고 싶다Roll로 공유 경계를 움직인다.선택 컷을 조금 늦게 보여주고 싶다Slide로 양옆 컷 시간을 보상한다.자동 음악 마커를 쓰고 싶다Beat Detection으로 구간·마디·박자 그리드를 확인한다.영상이 음악에 맞지만 기계적으로 느껴진다프레이즈와 동작 정점, 긴 컷·짧은 컷 대비를 설계한다.물속처럼 먹먹한 음악이 필요하다고역 필터와 자연스러운 복귀를 조합한다.슬로모션에서 물과 손이 찌그러진다원본 FPS와 프레임 보간을 비교한다.인물만 과거에 남고 배경은 움직여야 한다과거 프레임 인물을 분리해 원본 위에 합성한다.마스크를 넣으니 배경이 사라진다합성용 마스크와 효과 제한 마스크를 구분한다.컷마다 색이 달라서 조정 레이어로 못 맞춘다개별 교정 뒤 공통 룩을 적용한다.한국어 자동 자막·대사 검색이 안 된다확인된 영어 지원과 실제 설치 조건을 분리한다.재생이 끊기거나 저장 공간이 너무 크다Proxy·원본·캐시의 역할과 위치를 확인한다.XML을 가져왔는데 화면이 다르다색보정 전에 reference와 conform을 검수한다.다빈치 수정이 파이널컷에 바로 안 보인다새 렌더·명시적 교체가 필요한 구조를 이해한다.보정본을 늘리니 프레임이 없다handles 밖 수정은 재렌더가 필요하다.같은 원본의 두 컷이 같은 파일에 덮인다편집 인스턴스 Shot ID와 고유 파일명을 쓴다.QuickTime에서 색이 달라 보인다태그·입력 해석·중복 LUT·뷰어·레벨 순서로 진단한다.
